# zyz-worker 初始设计

## 目标

`zyz-worker` 计划成为一个面向 Agent CLI 的插件，帮助用户完成一条完整的工作链路。

当前的初始目标场景是：帮助用户完成一个已经确认的代码开发任务。

本文档只是第一版设计方向的占位文档，不是最终产品规格。

## 初始范围

第一版计划只支持一个工作流：

```text
完成一个已经确认的代码开发任务
```

工作流从用户已经明确要完成的任务开始。它暂时不负责业务目标发现、需求池管理，也不负责多个独立项目的调度。

## 规划流程

初始 Agent Team 流程如下：

1. 产品需求拆解
2. 技术实现设计文档
3. 编码实现
4. 测试验证
5. 完成总结

每个阶段都应产出可被下一阶段使用的中间结果。

## 概念角色

- 产品分析者：将已确认任务拆解为清晰的需求、约束和验收标准。
- 技术设计者：将需求转化为实现方案和测试策略。
- 开发者：根据技术设计完成代码实现。
- 测试者：执行有针对性的验证，并报告结果。

这些角色目前只是概念占位。第一版实现可以先用一个 Skill 工作流表达，不一定需要真实拆分为多个运行时 Agent。

## 当前非目标

- 不做多项目编排
- 不做自主产品发现
- 不要求后台服务
- 不强制使用 Node.js 运行时
- 在没有明确需求前，不引入 MCP server

## 待详细设计的问题

后续设计文档需要继续明确：

- 用户确认点如何设置
- 每个阶段需要产出哪些文档或结构化结果
- 这些产物应保存到哪里
- 如何在 Codex、Claude Code 等不同 CLI 中表达 Agent 角色
- 如何选择和执行测试命令
- 如何处理需求不清、实现阻塞和测试失败
