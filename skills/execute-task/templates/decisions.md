# 决定记录

本任务所有已定下的决定。每个 lane 的派发都引用本文件：lane 开工前读一遍，按这里的结论做；要做的事和某条决定冲突，或者需要一个这里没有的 A 类决定时，停下这一块、在 lane 报告里写明，交给主 agent。

只追加，不改写：某条决定被推翻时，追加一条新的，并把旧条目的 `状态` 改成"被 <新编号> 取代"。唯一会移动的是「等待回答的问题」：用户回答后，整条移到 A 类。

## 等待回答的问题

（评审裁决后当轮就问了用户、还没得到回答的问题。回答之前，设计里依赖它的部分保持原文、标为待定，不按推荐项先改；派发评审时把这些点列为"等用户决定"。用户回答后改掉依赖回答的部分，把这一条移到下面的 A 类并补上回答和结果。到设计批准闸门时仍未回答的，在闸门消息里逐条列出。没有就写 none。）

### Q-1: <一句话问题>

- 提出: （时间；评审点 + 轮次 + 发现编号）
- 影响的设计部分: （章节 / 模块；这些部分在回答前保持原文）
- 选项与推荐: （每项一行，标出推荐项和一句理由）
- 回答: （等待中；回答后填时间 + 用户原话要点，然后整条移到 A 类）

## A 类：用户决定

（架构、模块划分、关键算法、对外接口契约、持久化的数据结构、用户可见的行为；以及档位、设计批准、评审点停下交给用户后的选择（再开一轮 / 带着进实现 / 接受为遗留风险 / 拆成加固任务）、设计变更请求。拿不准是 A 还是 B 时按 A。一次提问的多个问题各记一条。）

- 时间:
- 来由: （提出方 main / <lane id> / review；实现中发现偏离时附 `file:line` 或复现）
