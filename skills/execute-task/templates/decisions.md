# 决定记录

本任务所有已定下的决定。每个 lane 的派发都引用本文件：lane 开工前读一遍，按这里的结论做；要做的事和某条决定冲突，或者需要一个这里没有的 A 类决定时，停下这一块、在 lane 报告里写明，交给主 agent。

只追加，不改写：某条决定被推翻时，追加一条新的，并把旧条目的 `状态` 改成"被 <新编号> 取代"。

## A 类：用户决定

（架构、模块划分、关键算法、对外接口契约、持久化的数据结构、用户可见的行为；以及档位、设计批准、评审点到上限后的选择、设计变更请求。拿不准是 A 还是 B 时按 A。一次提问的多个问题各记一条。）

### A-1: <一句话问题>

- 时间:
- 来由: （提出方 main / <lane id> / review；实现中发现偏离时附 `file:line` 或复现）
- 选项: （每项一行，标出推荐项）
- 用户回答: （原话要点；"全部按建议"记为采纳推荐项）
- 结果: （定下了什么；影响哪些设计章节、lane、文件；设计已更新 + 已重新派发，或设计按原样保留）
- 状态: 有效

## B 类：按推荐执行的决定

（以后能低成本改回来的实现细节：内部命名、配置键的默认值、内部函数怎么拆、日志措辞、内部错误码映射、依赖的小版本等。不停下来问，直接按推荐做并记在这里；设计批准时和最终报告里列给用户，用户可以否决任何一条。）

### B-1: <一句话决定>

- 时间 / 提出方:
- 决定:
- 推荐理由:
- 可逆性: （怎么改回、要动哪些地方、代价）
- 用户否决: （无；或 时间 + 用户原话要点 + 改成了什么）
- 状态: 有效
