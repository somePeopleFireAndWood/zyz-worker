# macOS `/tmp` → `/private/tmp` 软链陷阱

> 本文是 `skills/clean-tmp/SKILL.md` 第 0 步「枚举临时根」的配套参考资料，解释为什么每个临时根都必须先解析成**物理路径**再入表。

## 陷阱机制

macOS 上 `/tmp` 不是一个真实目录，而是指向 `/private/tmp` 的**符号链接**（同理 `/etc` → `/private/etc`、`/var` → `/private/var`）。这是 macOS 的历史布局，所有版本一致。

问题出在 `find` / `ls` 的默认遍历模式是**物理模式**（physical mode）：它们不跟随符号链接——包括**作为起点传入的那个软链**。于是：

```bash
find /tmp -maxdepth 1 -mindepth 1 -user "$(id -un)"
```

在 macOS 上的行为是：

1. `find` 把 `/tmp` 当作一个符号链接条目本身（depth 0）来处理，不展开进 `/private/tmp`。
2. depth-0 条目又被 `-mindepth 1` 排除。
3. 结果：**输出为空，且退出码为 0**——既不报错，也盘点不到任何东西。

## 为什么这很危险

clean-tmp 的安全网是「探测失败 → 保留 + 告知」。但这个陷阱的表现形态**不是失败**：命令干干净净地成功返回、输出为空。安全网根本不会触发，agent 会得出「/tmp 是空的，没什么可清理」的错误结论——macOS 侧的 `/tmp` 覆盖被**静默架空**。

需要强调失败方向：这是**欠报（under-report）**，绝不会导致误删——盘点不到的东西不会进删除清单。但「该清理面在 macOS 上完全失效」仍然是必须修掉的缺陷，尤其当用户依赖本 skill 做定期磁盘整理时，静默漏掉整个根意味着垃圾无限累积。

## 修法：入表前解析成物理路径

在把根加入 `ROOTS` 之前，用 `cd` + `pwd -P` 把它解析成物理路径：

```bash
r="$(cd "$1" 2>/dev/null && pwd -P)" || return 0
```

- `cd` 会正常跟随软链进入目标目录；`pwd -P`（`-P` = physical）打印**解析掉全部软链后的**绝对路径。
- macOS 上 `/tmp` 由此变成 `/private/tmp`，后续 `find`/`ls` 直接作用在真实目录上，陷阱消失。
- Linux 上 `/tmp` 本身就是物理路径，这一步是无害的恒等变换——因此无需 OS 分支，两端统一走同一段代码。
- 解析失败（目录不存在、无权限进入）→ 该根跳过、不入表，维持 fail→keep 的总方向。

顺带的好处是**去重**：macOS 上若 `$TMPDIR` 或其他候选根解析后与 `/private/tmp` 重合，物理路径比对能自然识别同一目录，避免对同一个根盘点两遍。
